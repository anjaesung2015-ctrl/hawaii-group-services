# 업무보고 — 지난 기록 모아보기 ('기록' 탭)

2026-10-15

## 왜

끝낸 일은 화면에서 내려간다. 안 끝낸 할 일은 완료할 때까지 오늘 탭 맨 위에 따라오지만(이월),
완료 체크를 하는 순간 그 항목은 오늘 목록에서 사라진다. 기록은 원래 날짜(`item_date`)에만 남아
있어서 `‹ ›` 로 그 날짜까지 되짚어가야 보인다.

사장님이 "마무리된 뒤에도 기록을 볼 수 있게" 요청한 것이 이것이다. 한 달치를 날짜별로 모아
한 화면에서 되짚어 보는 곳이 필요하다.

## 무엇을

`기록` 탭 하나. 읽기 전용. 오늘/내일 할 일(완료·미완료 모두)을 날짜별로 묶어 최신 날짜부터 보여준다.

- 주·월·연 자유메모는 넣지 않는다 — 날짜별 기록이 아니라 계속 고쳐 쓰는 메모라 섞으면 화면이 흐려진다.
- 달력·종합과 같은 `‹ 2026년 10월 ›` 월 이동. 쓰는 법을 새로 익힐 필요가 없고 한 번에 내려오는 양도 예측 가능하다.
- 이월(carryOver)은 적용하지 않는다. 기록은 원래 날짜에 그대로 있어야 한다.
- 상단 드롭다운을 그대로 따른다: `🏠 내 업무` → 사장님 기록, 직원 선택 → 그 직원, `👥 전체` → 사장님 + 직원 전원.
- **직원 화면에도 보인다 — 각자 본인 기록만**(2026-10-15 추가). 서버가 세션으로 강제하므로
  직원이 `staff_id` 를 바꿔 불러도 남의 기록은 나오지 않는다. 직원 응답에는 `people`(직원 명단)도 넣지 않는다.
  `근태`·`종합`은 그대로 사장님 전용(`BOSS_TABS`).

## 서버

```
GET /api/report/history?month=YYYY-MM[&staff_id=]
```

- 세션 필수. 직원이 부르면 `staff_id` 를 무시하고 본인 것만 — 서버가 강제한다.
- 사장님: `staff_id` 지정 → 그 사람. 미지정 → 활성 직원 전원 **+ 사장님 본인**(사장님 기록이 빠지면 이 화면의 뜻이 없다). 사장님을 맨 앞에 둔다.
- `period IN ('today','tomorrow')`, `item_date LIKE 'YYYY-MM-%'`.
- 제목·메모가 둘 다 빈 항목은 제외 — `+ 항목 추가`만 누르고 둔 빈 줄은 기록이 아니다.
- 잘못된 `month` → 400 `bad_month`.

응답:

```json
{
  "month": "2026-10",
  "people": [{ "id": 1, "name": "미가" }],
  "rows": [
    { "date": "2026-10-14", "total": 2, "done": 2,
      "items": [{ "id": 9, "staff_id": 6, "name": "사장님", "item_date": "2026-10-14",
                  "title": "직원 급여 이체", "memo": "", "done": 1, "from_boss": 0 }] }
  ]
}
```

`rows` 는 날짜 내림차순, 날짜 안에서는 입력 순서(`id`). `people` 은 달력과 같은 활성 직원 목록 —
사람별 색(`colorOf`)을 달력 범례와 똑같이 맞추는 데만 쓴다.

## 화면

`app.js` 에 탭 `hist` 와 `renderHistory()` · `historyCards(rows, allMode)` 추가.

- 날짜별 카드: 머리글 `10/14 (수)` + 오른쪽에 `2/2 완료`
- 항목: `✓ / ○` + 제목 + `· 메모`, 사장님 지시는 📌 뱃지
- `전체` 모드에서는 항목 앞에 사람 이름을 색 뱃지로
- 그 달에 기록이 없으면 `기록 없음`
- 입력칸·삭제 버튼 없음. 고칠 일이 있으면 해당 날짜의 `오늘` 탭에서 고친다.

`historyCards` 는 순수 함수로 두어 브라우저 없이 렌더 결과를 검사한다.

`i18n.js` 새 문구는 `hist` 하나(기록 / Бүртгэл). 나머지는 기존 문구 재사용
(`calTitle`·`dayFmt`·`doneCount`·`scNone`·`noTitle`·`boss1`).

## 건드리지 않는 것

로그인·SSO, `report_items` 스키마, 이월 동작, 달력, 종합, 근태. DB 마이그레이션 없음 —
기존 데이터를 다르게 읽을 뿐이다.
